{% load i18n %}{% comment %} One form field, rendered the same way everywhere. Order is label → errors → widget → help. The errors sit *above* the input on purpose, and not only because reading the problem before the thing that has it is the better order: the stylesheet turns the field's border red with `.errorlist + input`, which is an adjacent-sibling rule and only fires when the list is immediately before the control. With the errors underneath, as they were, that border never appeared and a long form gave you no way to spot which field had failed without reading every message. Required is marked before submission, not discovered after it. The asterisk is aria-hidden and paired with sr-only text, because a screen reader announcing "asterisk" is noise — `required` on the widget itself is what the accessibility tree actually uses, and Django puts it there. Use for a whole form: {% for field in form %}{% include "_field.html" %}{% endfor %} or for one field at a time: {% include "_field.html" with field=form.company_name %} {% endcomment %} {% if field.is_hidden %} {{ field }} {% else %} {{ field.errors }} {{ field }} {% if field.help_text %}{{ field.help_text }}{% endif %} {% endif %}
